# Update Epic

Status: To Do
Task ID: TM-19

### 📌 Goal

Allow users to **update Epic details directly from the Epic Details popup**, including:

- Title
- Description
- Assignee
- Deadline

All updates should be saved via the API and reflected immediately in the UI.

---

## 🗺️ Context

- Feature lives inside the **Epic Details modal**.
- User edits fields **inline** without navigating away.
- Updates apply to the selected epic only.
- Project members are used as possible assignees.

---

## 🎯 Editable Fields & Behavior

### 1️⃣ Epic Title

- Editable text input
- Pre-filled with current title
- Required field
- Save on: **Blur**

---

### 2️⃣ Epic Description

- Editable textarea
- Pre-filled with current description
- Optional
- If empty → display: `No description provided`
- Save on: **Blur**

---

### 3️⃣ Assignee

- Clicking on the **assigned user** switches the field into **edit mode**
- Edit mode shows a **select dropdown**
- Dropdown options:
    - Project members only
    - Display user name + avatar (if available)
- Selection rules:
    - Selecting a user assigns the epic
    - Selecting “Unassigned” removes the assignee
- Save immediately on selection

---

### 4️⃣ Deadline

- Editable date picker
- Pre-filled if deadline exists
- Optional field
- Clearing the date removes the deadline
- Save on: C**hange**

---

## 🔗 API Details

### Route

```
PATCH /rest/v1/epics
```

### Query Parameters

```
id = eq.{epic.id}
```

### Request Headers

```
apikey: <API_KEY>
Authorization: Bearer <ACCESS_TOKEN>
Content-Type: application/json
```

### Request Body (Partial Update)

```json
{
	"title": "Updated epic title",
	"description": "Updated epic description",
	"assignee_id": "user-id-or-null",
	"deadline": "2026-01-30"
}
```

Only send the fields that were changed.

---

## 🔄 UI State Handling

### Success

- Update UI immediately

### Error

- Revert to previous value
- Show toast error message: `Failed to update epic. Please try again.`
